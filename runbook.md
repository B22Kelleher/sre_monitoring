# System Monitoring Runbook

## Overview

This runbook provides steps to diagnose and resolve alerts generated by the Prometheus + Grafana monitoring system.
The system monitors CPU, memory, disk usage, and instance availability using Node Exporter.

Alerts are triggered in Grafana and sent via SMTP email.

## Alert Definitions

### High CPU Usage

* Trigger: CPU usage > 80% for 5 minute

### Extreme CPU Usage

* Trigger: CPU usage > 90% for 1 minute

### High Memory Usage

* Trigger: Memory usage > 90%

### High Disk Usage

* Trigger: Disk usage > 90%

### Instance Down

* Trigger: `up == 0`

---

## High CPU Usage

### Diagnosis

1. Check Grafana dashboard → CPU Usage panel
2. Identify spike timing and duration
3. Run:

```
top
```

4. Identify processes consuming high CPU

### Resolution

* Kill runaway process:

```
kill -9 <PID>
```

* Restart affected service if necessary

### Verification

* CPU usage drops below threshold
* Grafana alert returns to **Normal**

---

## Extreme CPU Usage

### Diagnosis

* Same steps as High CPU, but prioritize immediate action

### Resolution

* Restart system service or container:

```
docker restart <container_name>
```

### Verification

* CPU stabilizes below 80%
* Alert clears in Grafana

---

## High Memory Usage

### Diagnosis

1. Check Grafana → Memory Usage panel
2. Run:

```
free -h
```

3. Identify memory-heavy processes:

```
top
```

### Resolution

* Restart process consuming excessive memory
* Clear caches if necessary:

```
sync; echo 3 > /proc/sys/vm/drop_caches
```

### Verification

* Memory usage decreases
* Alert resolves

---

## High Disk Usage

### Diagnosis

1. Check Grafana → Disk Usage panel
2. Run:

```
df -h
```

3. Identify large files:

```
du -ah / | sort -rh | head -20
```

### Resolution

* Delete unnecessary files
* Clean logs:

```
rm -rf /var/log/*.log
```

### Verification

* Disk usage drops below threshold
* Alert clears

---

## Instance Down

### Diagnosis

1. Check running containers:

```
docker ps
```

2. Verify Node Exporter status
3. Test metrics endpoint:

```
curl localhost:9100/metrics
```

### Resolution

* Restart Node Exporter:

```
docker restart node-exporter
```

* Restart full stack if needed:

```
docker-compose down
docker-compose up -d
```

### Verification

* `up == 1` in Prometheus
* Metrics visible in Grafana
* Alert resolves

---

## Alert Status Monitoring

* Alerts can be viewed in the Grafana **Alert Status panel**
* States:

  * **Normal** → system healthy
  * **Pending** → threshold breached but waiting
  * **Firing** → alert active

---

## Alert Routing

* Alerts are sent via **SMTP email**
* Configured in Grafana Alerting
* Triggered when thresholds are exceeded or system becomes unavailable

---

## General Troubleshooting

### Restart Monitoring Stack

```
docker-compose down
docker-compose up -d
```

### Check Prometheus Targets

* Visit: `http://localhost:9090/targets`
* Ensure node-exporter is **UP**

### Check Grafana

* Visit: `http://localhost:3000`
* Confirm dashboards and alerts are active

---

## Notes

* Monitoring interval: 5 seconds
* Alerts are designed for short detection windows (1 minute)
* System assumes a single-node setup with Node Exporter
